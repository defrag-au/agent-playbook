# rmcp 1.3 (Model Context Protocol SDK for Rust)

Official SDK: https://github.com/modelcontextprotocol/rust-sdk

## Cargo.toml

```toml
rmcp = { version = "1.3", features = ["server", "macros", "transport-io"] }
schemars = "1"
```

## Simplest Pattern: `#[tool_router(server_handler)]`

Combines tool definitions AND ServerHandler in one impl block.
No separate `tool_router` field needed. No separate `#[tool_handler]` impl.

```rust
use rmcp::{handler::server::wrapper::Parameters, schemars, tool, tool_router};

#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
pub struct SumRequest {
    #[schemars(description = "the left hand side number")]
    pub a: i32,
    pub b: i32,
}

#[derive(Debug, Clone)]
pub struct Calculator;

#[tool_router(server_handler)]
impl Calculator {
    #[tool(description = "Calculate the sum of two numbers")]
    fn sum(&self, Parameters(SumRequest { a, b }): Parameters<SumRequest>) -> String {
        (a + b).to_string()
    }
}
```

## Full Pattern: Separate `#[tool_router]` + `#[tool_handler]`

Use when you need custom ServerHandler (instructions, resources, etc.)

### Imports

```rust
use rmcp::ErrorData as McpError;
use rmcp::handler::server::router::tool::ToolRouter;
use rmcp::handler::server::wrapper::Parameters;
use rmcp::model::*;
use rmcp::{ServerHandler, ServiceExt, tool, tool_handler, tool_router, schemars};
```

### Server Struct

Must be `Clone`. Must have `tool_router: ToolRouter<Self>` field.

```rust
#[derive(Clone)]
pub struct MyServer {
    tool_router: ToolRouter<Self>,
    // your state...
}

impl MyServer {
    pub fn new() -> Self {
        Self {
            tool_router: Self::tool_router(), // generated by #[tool_router] macro
        }
    }
}
```

### Tool Input Types

```rust
#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
pub struct SearchInput {
    #[schemars(description = "description shown to LLM")]
    pub query: String,
    #[serde(default)]
    pub limit: Option<u32>,
}
```

### Tool Router

```rust
#[tool_router]
impl MyServer {
    // Tool with params — destructure via Parameters wrapper
    #[tool(description = "Search for things")]
    async fn search(
        &self,
        Parameters(input): Parameters<SearchInput>,
    ) -> Result<CallToolResult, McpError> {
        let query = &input.query;
        Ok(CallToolResult::success(vec![Content::text("result")]))
    }

    // Tool with no params
    #[tool(description = "List everything")]
    async fn list_all(&self) -> Result<CallToolResult, McpError> {
        Ok(CallToolResult::success(vec![Content::text("items")]))
    }

    // Simple tool — can return String directly
    #[tool(description = "Say hello")]
    fn hello(&self) -> String {
        "hello".to_string()
    }
}
```

### ServerHandler

```rust
#[tool_handler]
impl ServerHandler for MyServer {
    fn get_info(&self) -> ServerInfo {
        ServerInfo::new(
            ServerCapabilities::builder()
                .enable_tools()
                .build(),
        )
        .with_server_info(Implementation::from_build_env())
        .with_protocol_version(ProtocolVersion::V_2024_11_05)
        .with_instructions("Description for LLMs.".to_string())
    }
}
```

## Server Bootstrap (main.rs)

```rust
use rmcp::{ServiceExt, transport::stdio};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt()
        .with_env_filter(
            tracing_subscriber::EnvFilter::from_default_env()
                .add_directive(tracing::Level::WARN.into()),
        )
        .with_writer(std::io::stderr)
        .with_ansi(false)
        .init();

    let service = MyServer::new().serve(stdio()).await?;
    service.waiting().await?;
    Ok(())
}
```

## Error Handling

```rust
Err(McpError::invalid_params("message", None))
Err(McpError::internal_error("message", None))
```

## Key Differences from 0.12

- `ServerInfo::new(capabilities).with_server_info(...).with_instructions(...)` builder pattern
  (not struct literal)
- `ServerCapabilities::builder().enable_tools().build()` (not struct literal)
- `Implementation::from_build_env()` reads Cargo.toml name/version
- `ProtocolVersion::V_2024_11_05` (underscore-separated)
- `#[tool_router(server_handler)]` shorthand combines everything for simple servers
- Tools can return `String` directly (not just `Result<CallToolResult, McpError>`)
- `rmcp::transport::stdio()` (not `rmcp::transport::io::stdio()`)
